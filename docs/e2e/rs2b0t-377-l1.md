# Revision 377 L1 live milestone

Run from the repository root against an operator-owned revision 377 engine. Do not start, stop, rebuild, or repack the engine.

```sh
bun tools/nav/build-collision.ts --engine "$ENGINE_DIR"
bun e2e/rs2b0t-377-l1.ts --engine "$ENGINE_DIR" --content "$CONTENT_DIR" \
  --origin http://127.0.0.1:81 --seed-html --account-prefix l1x --out "$EVIDENCE_DIR/run-1"
```

The output directory must not exist. Each run creates one disposable account with a random secret.
Use `--account-prefix` to select your agent's prefix (default `l1x`). The prefix must contain one to five lowercase letters or digits.
The account appends three random hexadecimal characters. The 16-character secret stays outside receipts and recordings.

## Assertions

1. Deploy a strict client with the engine's public RSA parameters into an isolated page and bundle directory.
2. Log in and reach scene state 2. Accept character design through the product action.
3. Walk one tile east. Assert the exact server tile, including the unchanged level and north coordinate.
4. Read `::getvar tutorial` and assert the server value equals 1.
5. Talk to the RuneScape Guide. Decline the optional tutorial skip. Finish the normal dialogue and assert server tutorial state 4.
6. Assert client varp 406 equals 1 and `::getvar tutorial_progress_overlay` agrees. Save a scene screenshot and a quiescent checkpoint.
7. Log out through the product action. Assert the stream is null, the session is inactive, and login credentials are cleared.
8. Log in again. Assert a new player object, a new capture segment, cleared selection/menu/input state, a built scene, and persisted tutorial value 4.
9. Log out cleanly. Finalize the tap recording and cache bundle.
10. On a separate page, alter only the client's public RSA modulus. Assert observed login replies `[0, 6]` and no active session.
11. Replay the recording through the production runtime. A replay error fails the cell.

The wrong-key attempt bypasses the tap because the tap refuses undecryptable login requests. It does not change the engine key.

A failed receipt records the failing stage. Classify each failure before changing an assertion:

- **Product:** client decoding, rendering, input, or session lifecycle differs from the server contract.
- **Oracle:** the cell or replay assertion is incorrect.
- **Fixture:** archives, content, account, or required engine setup does not match the declared inputs.
- **Interference:** another account or process changes the observed scene or service.

It checks again after archive fetches. It preserves named OnDemand completion failures before closing connections.
Truncated streams still fail. The tap tests cover delayed completion, an active archive fetch, and retained failure predicates.

The cell now stores returned server and client varp values instead of constants.
